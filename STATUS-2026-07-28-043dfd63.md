- 10:40 **Decision — spine:** sensor instruments (the world) + probability made tangible (ideas). Unifying thesis adopted:
  > *Every item is an instrument. You touch it with your thumb and numbers come out.* Some point outward at physical reality (level, dB meter, tuner, seismograph); some point inward at mathematical reality (Monte Carlo, Bayes, Benford). Same grammar, same shelf — **a cabinet of instruments.**
  - Rejected: quantified-self tracker (crowded, needs storage/sync) and calibration training (good, but parked as a possible later tenant).
- 10:52 **Decision — stack: no-build vanilla ES modules, with JSDoc types.** User pushed back and asked for an honest case for Vite/Preact before committing; we discussed it properly.
  - B's only two real wins were TypeScript and Workbox's content-hashed SW precache manifest. Both are obtainable inside A: `// @ts-check` + JSDoc + `jsconfig.json {checkJs:true}` + `tsc --noEmit` as a gate gives full type checking on files that ship byte-for-byte; a ~40-line `tools/build_sw.py` gives hashed precaching, matching the existing `build_feed.py` pattern.
  - **Deciding argument was phone debugging.** Sensor code can only be debugged on-device; user is on Artix, so iOS Safari remote-debug (which wants a tethered Mac) is already the hardest problem. Bundling would make the only available view of it indirect. No-build means the file you inspect on the phone is the file you wrote. Also aligns with the standing "works for the greater Aegix Linux community" instruction.
  - **Tripwire recorded for revisiting B:** if the site ever grows a real application-state layer (accounts, sync, large shared data model, many interlocking views). A cabinet of instruments does not trip it.
  - Dependencies, if ever needed, get vendored into `vendor/` as ES modules — no npm at runtime or build time.
- 10:55 **Open logistics item (affects either stack):** DeviceMotion/mic/camera need a secure context, and a phone on the LAN is not `localhost`. Options: `caddy` local HTTPS, `mkcert`, or a `staging.thequantitative.com` vhost. Leaning staging vhost — it exercises the real service worker and install flow, which local dev cannot simulate.
- 10:58 **§1–§2 approved by user.** Routes `#/`, `#/i/<id>`, `#/about`. Instrument contract: one self-contained file per instrument, default-exporting `{id,name,category,blurb,needs,mount(root,ctx)}` where `mount` returns its own teardown closure. Registry holds eager metadata + lazy `import()`.
  - Key design point: the shell hands instruments a **managed resource kit** (`ctx.raf`, `ctx.on`, `ctx.audio`, `ctx.mic`, `ctx.motion`, `ctx.signal`, `ctx.store`) rather than raw browser APIs, so an orphaned rAF loop or a live AudioContext draining the battery after navigation becomes structurally hard instead of a discipline problem. Permission handling lives entirely in the shared arm screen — no instrument file contains permission boilerplate.
